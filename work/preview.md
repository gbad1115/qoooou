# Pretrain && CPT：
数据规模，数据质量和数据多样性决定模型性能。
pretrain是为了建立丰富的语义表征空间（需要几十TB级别的数据），目标是预测next token。
实际常见做法是在SFT RL取得初版模型后开始CPT（已经训练好的基座模型（Base Model）基础上，使用特定领域或新增的无监督数据，继续进行大规模的自回归训练）。
continue pretrain（仅参考），SFT不注入知识，只是对齐模型的表达。CPT阶段数据规模小于pretrain。重点加入高质量垂类数据，并且应该是pre没见过的，这部分的过滤需要强LLM从多维度打分筛选信息含量高的数据，其次是进行改写，对于代码类任务，可以进行结构化的代码重写。后续还是pretrain那一套。

流程： **爬数据，做处理，搞架构**
数据来源多样，爬的，开源数据，内部数据，合成的。 然后数据去重，质量过滤，规则过滤，数据配比。

数据去重：包含精确去重和模糊去重，前者利用 MD5 或 SHA256 算法对文档求哈希值，直接删除完全一致的重复项。文本数据通常使用Minhash+LSH，将文档拆分为 N-gram 集合，通过 MinHash 压缩成签名，再利用 LSH 将相似文档聚类到同一个桶中进行对比。这一步往往会过滤30%的内容，最终提升数据的质量密度。

去重后一般是过滤，基于PPL的形式，使用一个在高质量语料上训练的小型语言模型去预测目标文本。 如果 PPL过高，说明文本不符合人类语言表达习惯；如果 PPL 过低，说明文本可能是机械重复的。这两种都会被过滤掉，阈值看数据分布。
另一种是FastText过滤（字符级 N-gram）。需要万级别的正负样本label打标，训练预测，输出一个文本质量分数。推理训练都很快（层次化 Softmax分类，logk级别），适合大规模处理。
启发式规则过滤，Gopher：对文本长度约束，符号与结构约束（符号与单词的比例必须小于 0.1），停用词约束（包含一定的"the", "is"...），内容重复性约束解决复读，如果文档中最高频的 n-gram（如 3-gram, 4-gram）占比过高，则判定为低质量，通常依赖于人工设定阈值。

数据配比决定各种类型的数据如何混合。文本而言包含网页，代码，数学，常识，小语种等等。传统是通过小规模实验（8B 模型等）观察不同比例对下游任务的影响，然后等比例放大到大模型。上采样高质量的，下采样低的。也有动态调整的算法（Google），训练一个小的参考模型，该模型在各领域分布均衡。然后训练一个代理模型，通过调整各领域的权重，试图最小化其相对于参考模型的交叉熵。通过 Min-Max 优化自动计算出能让模型在所有领域上Loss下降最均衡的权重。或者采用课程学习在训练的最后10%阶段，将配比切换为高质量的、专业性强的数据。 最后除了训练集，还要有高质量的eval dataset，看eval loss判断新加入的数据有没有用。最后对所有业务训练而言，保证训练和测试数据的同分布。

数据序列化与大规模训练优化
大规模训练中，为了最大化吞吐量必须将原始文本预处理为二进制格式（如 .bin 或 .idx）。
使用指定的 Tokenizer 将全量文本转化为整数数组，Megatron-LM脚本执行。实现 Memory Mapping，消除训练时的 I/O 和分词瓶颈。Packing 将短文本拼接，并用特定的 sep_token 分隔。在 TB 级训练时，多机之间的梯度同步All-Reduce往往比计算还慢。NCCL 优化 或 节点内 NVLink 的配置。


# SFT训练
参数设置：一般来说1到3个 epoch。主要注意训练时的超参控制，调整并行策略dp tp pp，zero3等等，offload还可以实现参数卸载到内存。参考loss的尖刺可能存在噪声，检查或者调大batchsize，不同模型的lr需要多跑实验测试。batchsize过大无法充分学习到数据，总step也会下降，大batchsize容易收敛到局部最优解，小的更容易找到平坦的极值点，更抗参数扰动，泛化会更好。
packing填充，防止语义污染，Packing 必须配合特殊Attention Mask 使用，每条样本的 position_ids 通常会重置。

数据构造：构造问答对，最后只计算answer部分loss。确保提示词的质量，基于同一个模型设计几版不同的提示词，观察badcase，进行迭代提示词。 确保数据本身的准确性，让强LLM判断答案正确与否，可以筛选出当前模型回答的不好的问题，后面训练时可以从中进行采样。然后是数据改写， 具体做法是将过滤后的数据根据原始答案和常见错误，一步步检查生成更好的答案。
对业务能力的提升，任务分解：对于模型的任务多步链式需求，采取任务分解的思路，对每个子任务构造数据实现每一步的能力提升，再加入完整的任务数据。另一个是混合部分相关的业务数据（针对数据不多的任务）。实际的SFT两阶段微调，解决冲突问题或者单阶段无法完成的复杂任务。先练 A 后练 B，和先练 B 后练 A 的效果完全不同。通常建议先练知识密集型任务，再练逻辑/格式化任务。例如多任务学习将任务解耦，分别在子任务集上进行训练，确保每个原子能力都达到阈值。第二阶段使用全任务混合的高质量数据进行小学习率训练，完成能力整合。

# RL
RL是一种“非平稳”过程。相比SFT，RL 依赖于模型当前的输出进行采样。使用极低的学习率且通常KL散度的惩罚约束，参数的更新幅度更小，且集中在主导概率分布的深层网络（决策）。
训练过程中，一般看这几个
reward：持续上升？
业务指标（准确率）：是否同步上升。没用的话调整奖励设计。
策略熵Policy Entropy：如果熵值迅速降至极低0.2这种，说明发生了模式坍缩，模型学会了用特定的“套话”来刷分，丧失了生成多样性。
KL：KL 应该缓慢增加并最终趋于平稳。如果 KL 激增，说明模型正在剧烈改变行为，极易发生“灾难性遗忘”，导致通用能力丧失。
生成长度：衍生推理链的趋势。
奖励函数一般有格式和正确性奖励，后者权重更大。开放问题借助强模型judge。

其他：业务基模，主要专注业务场景的上的表现，通过模型训练能达到同时在不同公开测评集上和基础模型能力保持接近或更好。和垂类的搜索 广告等业务做区分。对Tokenizer和Context Window的讨论。业务场景（如搜索、长文理解）对长文本的需求极高。
对比base应该有：
1.具备通用性与迁移能力，另外可以作为业务的更高起点实现快速迭代。例如同一份业务数据对业务基模A和base模型B，训出来的A1比B1表现更优。
2.不训练直接推理时效果更好。业务中会需要使用一个很强的教师模型对问答产出gold answer，在利用这些去训练一个小的模型（都可以蒸）。如果业务基模的模型在业务上表现更好，可以替代相应的instruct模型。
