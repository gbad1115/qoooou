工作一：SFT 合版训练
首先，项目背景是因为当时模型侧存在多条不同的搜索链路，不同链路分别维护各自的训练组织和能力形态，导致整体迭代成本较高，同时模型能力也比较分散。因此我们的目标是将原有多个搜索组织整合为统一的agent链路，希望在保持通用问答基准性能稳定的基础上，进一步强化模型在搜索场景下的指令遵循、多轮交互以及时效性问答等能力。服务于不同能力、不同链路、不同产品场景的数据、训练目标、Prompt、工具协议和评测体系进行统一。
主要难点在于不同来源的数据分布和能力目标并不一致。一方面，搜索场景数据更强调指令跟随、时效信息和多轮交互；另一方面，主模对齐数据更偏向通用问答和基础能力保持。如果直接将多源数据进行简单混合训练，模型很容易出现能力相互干扰，导致一部分能力增强的同时，另一部分能力明显退化。
在初始实验中就观察到，将全部数据直接混合后，模型在搜索Bench上出现了显著性能退化，其中复杂指令和时效两个子任务分别掉点 1.32pp 和 0.85pp。进一步做消融实验后，我们发现问题的核心并不只是“数据量不够”或者“训练轮数不足”，而是不同数据源之间的质量差异和配比方式不合理。
因此，为了解决这个问题，我们没有继续沿用“统一混合、等权训练”的方式，而是转向了更精细的数据组织策略。具体来说，一方面我们引入了hy主模对齐数据和开源数据，用于稳定模型的基础问答能力；另一方面，我们针对多源数据设计了非对称权重配比方案，根据不同数据源对搜索能力和通用能力的影响程度，动态调整其在训练中的占比。

最终，这个方案取得了比较好的效果。相比初始版本，模型在搜索时效 Bench 上提升了 1.46pp，同时在基础问答 Bench 上也实现了 0.02pp 的正向提升，说明我们最终找到了一个能够兼顾搜索增强和通用能力保持的合版训练方案。

聊具体的实效性，数据是怎么构造的，加了哪些数据？
我理解这块的核心是围绕模型短板构造可训练信号。首先从线上日志、badcase、人工评测集和工具调用日志中挖掘高价值样本，比如该搜不搜、不该搜乱搜、工具选错、参数生成错、证据整合错等。然后对这些样本做归因、去重、分层采样，形成高质量训练集。
Synthetic Data主要用于补充真实数据覆盖不到的边界场景，比如通过模板、强模型和反事实改写生成“必须搜索 / 不需要搜索 / 弱搜索意图”的对比样本，帮助模型学会细粒度边界。
Trajectory 则是 Agent 后训练里非常关键的数据形式，它不只包含最终回答，还包含完整动作过程，比如 plan、tool_call、observation、retry、final_answer。它可以训练模型是否调用工具、调用哪个工具、如何生成工具参数、工具失败后如何恢复，以及如何基于证据生成答案。实际训练中可以把 good trajectory 用于 SFT，把 good/bad trajectory pair 用于 DPO 或 reward model 训练。（有什么好的做法）
训练上，Agentic Search 通常先通过 prompt 和工程 controller 定义执行流程，让模型能调用 search、open等工具；然后构造包含 tool call 轨迹的 SFT 数据，让模型学习什么时候搜、怎么拆问题、怎么生成 query、什么时候继续搜、什么时候停止以及如何基于证据回答。训练时一般 mask 掉 user 和 tool observation，只对 assistant 的决策、工具调用和最终回答算 loss。

工作二：联网策略触发优化
这个项目的出发点，是因为线上搜索链路当时同时存在两套并行逻辑：一套是模型自动判断是否需要联网搜索（意图），另一套是用户通过手动开关显式触发搜索（need search）。而原有训练数据主要覆盖的是“搜索默认自动触发”的场景，对于手动开关以及不同搜索意图下的触发边界覆盖不足，因此模型在线上会出现“该搜的时候不搜，不该搜的时候又触发搜索”的问题，影响整体的搜索触发准确率和用户体验。
这个项目的主要难点在于，联网搜索触发本质上是一个意图判断问题，而且这个判断和普通问答能力是强耦合的。也就是说，如果搜索触发策略过于激进，会导致大量本可以直接回答的问题被不必要地送去搜索，影响回复效率和模型稳定性；但如果触发策略过于保守，又会让模型在需要实时信息、外部事实或者时效知识时无法及时调用搜索能力。因此这里的关键不是单纯提升“触发率”，而是提升“触发准确率”。
为了解决这个问题，我们首先使用了自动化打标工具，对训练样本进行识别和筛选，尽可能找出那些真正需要联网搜索的样本，构建更贴近线上决策边界的数据集合。在此基础上，我们围绕“搜索意图”设计并实施了多阶分布配比实验，核心思路是：不是把所有需要搜索的样本简单混在一起训练，而是根据搜索意图强弱、触发必要性以及不同场景的分布特征，对训练数据进行更细粒度的分桶和配比调整，从而让模型更好地学习“什么情况下应该触发联网，什么情况下应该直接回答”。
通过这套方法，我们逐步校准了模型对搜索意图的判断边界，在不破坏模型基础问答能力的前提下，提升了其对联网需求的识别能力。最终结果上，模型的联网触发准确率提升了 3pp，同时基础问答能力保持稳定，达到了比较符合线上目标的优化效果。
主模是通用 LLM，主要负责理解、推理和生成，回答更多依赖模型参数中的知识；Agentic Search 是在主模基础上加上搜索工具、controller 和多轮检索流程形成的搜索型 Agent 能力。它不是简单联网，而是包含搜索触发、问题拆解、query 生成、多轮检索、证据阅读、信息充分性判断和最终 grounded answer 生成。
为什么合版：多个专项重复维护相似的数据清洗逻辑、训练脚本、量化与部署流程，难以进行知识沉淀。
主模数据占优会提升搜索时效 Bench：搜索数据会放大工具调用噪声。高质量主模数据可以稳定模型的基础指令理解和答案生成能力，搜索数据负责教会工具使用和时效行为，两者需要平衡。
