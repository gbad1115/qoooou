## 0. 一句话总览

把 576 个视觉 token 切成 58 段 → 每段挑一个**真实存在的代表 token**（锚点）→ 用一个小网络学习"每个锚点该往哪个方向修正、修正多少"→ 输出 58 个仍在真实 token 流形附近的向量喂给 LLM。**压缩器全程只看图像，不看问题。**

与旧路线（v9–v15 的"打分→top-k 选择"）的根本区别：旧路线学习"选哪些 token"（离散、不可微、易塌缩），本路线学习"在固定代表点周围怎样融合残差"（连续可微、恒等起步、输出恒在真实 token 流形上）。

## 1. 符号总表

| `n₁ = 58` | 压缩后输出行数（评测记号 "@58"）；压缩比 N/n₁ ≈ 9.93× |

| `π` | 冻结的 LLaVA 多模 projector（1024→4096） |
| `f_θ` | 冻结的主干 LLM（LLaVA-1.5 语言模型） |
| `e_k, S_k, L_k` | 第 k 段的边界索引 / token 集合 / token 数 |
| `a_k` | 第 k 段的锚点（一个真实 token） |
| `r_i, w_i, τ` | 残差 / softmax 聚合权重 / 温度 |
| `μ_k, σ_k` | 段统计量：加权残差均值 / 标准差（**v1 另有 m̄_k 平均相似度、ℓ_k = ln L_k，v2 决议删除**，见 §6 注） |
| `δ_k` | 学习到的残差写入量（d 维向量） |
| `γ(v_k), g_k` | 门控（v1：长度 n₁ 的可学习标量表；**v2：由 v_k 驱动的共享网络**，见 §7 / §15.3a）/ tanh 后的门控值 |

## 2. 压缩器的输入

```
X = π( φ(img).hidden_states[-2][:, 1:] )  ∈ ℝ^{576×4096}
```

- `φ(img)`：CLIP ViT 输出；`[:, 1:]` 去掉 CLS token；`[-2]` 取倒数第二层 hidden state（对应 LLaVA 配置的 `vision_feature_layer=-2`）；再过 projector `π` 升到 LLM 的 4096 维。
- **φ、π 全程 frozen**（`requires_grad=False`），压缩器只能接触 X。
- 问题文本 q 与答案 a 只在训练时用于教师前向与 Loss 计算，**从不进入 C 的生成路径**——这是"问题无关"的第一重保险（评测时压缩器也完全不读问题）。
- 选择在 projector **之后**的空间学习，意味着锚点与残差都已经是 LLM 语义空间中的量，LLM 看到的输入分布与未压缩时同源。

## 3. 第一步：分段（覆盖由构造保证）

```
e_k = linspace(0, N, n₁+1).long()        k = 0, …, 58
S_k = {e_k, e_k+1, …, e_{k+1}−1}         L_k = e_{k+1} − e_k  ≈ 10
```

把按 raster 顺序（行优先展开的 24×24 网格）排列的 576 个 token 切成 58 个**连续局部区域**，每区约 9~10 个 token。

白话：无论图像内容如何，这 58 块拼图**每一块必出一个代表**，空间覆盖 58/58 由切分方式白送，不依赖任何学习。对照：旧 free top-k 路线自由选出的 58 个 token 只覆盖 40/58 段，是 v12/v13 的主要死因之一。

## 4. 第二步：medoid 锚点（无参数、确定性）

```
z_i = x_i / ‖x_i‖                                  单位化
s_i = (1/L_k) Σ_{j∈S_k} z_iᵀ z_j                   token i 与段内全员的平均余弦
ν_i = ‖x_i‖ / max_{j∈S_k} ‖x_j‖                     归一化范数（破并列用）
α_k = argmax_{i∈S_k} ( s_i + 1e-3·ν_i )
a_k = X[ e_k + α_k ]                                ← 一个真实存在的 token
```

- `s_i` 衡量"i 与这个段的平均水平有多像"，最像的那个就是段的 **medoid**（几何中心在集合中的代表）。
- 锚点是**从 576 个真实 token 中挑出来的，不是合成向量**——它必然位于 LLM 训练时见过的视觉 token 流形上。
- 选择过程：零可学习参数、完全确定性、只读图像 ⇒ 任何 seed 下锚点集合一致，训练/推理无随机性差异。
- `1e-3·ν_i` 只是余弦并列时的微小破平项，防止选到范数异常的点。

## 5. 第三步：段内残差 + softmax 加权

```
r_i   = x_i − a_k                     残差：锚点"看不见"的那部分信息
sim_i = cos(x_i, a_k) = x_iᵀa_k / (‖x_i‖‖a_k‖)
u_i   = MLP_res(r_i) + sim_i          MLP_res: ℝ^d → 256 → GELU → 1
w_i   = softmax(u / τ)_{i}            τ = 1.0
```

- `r_i`：每个真实 token 相对锚点的差。锚点是"平均脸"，残差里装的是"个性"。
- `u_i` 两项：`sim_i` 是与锚点的原始相似度；`MLP_res(r_i)`（代码中 `res_score`）对残差结构打分——这是压缩器**唯一的逐 token 打分能力**，但它只决定"聚合时谁占多少权重"，不决定"选不选"。
- softmax 使 `w_i` 连续、可微、加权和为 1，梯度干净流回 `MLP_res`。对照旧路线：那里 softmax/Gumbel 作用在"选不选"上（离散 top-k 的连续近似），选择端一崩溃全盘皆输；这里作用在"聚合权重"上，天然无此故障模式。
- 诊断：权重熵 `H(w) = −Σ w_i ln w_i` 从 1.82 → 1.02 nats（均匀上限 ln 10 ≈ 2.3），说明训练确实让权重收缩到少数关键残差上。

## 6. 第四步：段统计量 → 写入量

```
μ_k   = Σ_i w_i · r_i                            加权残差均值（d 维）
σ_k   = ( Σ_i w_i (r_i − μ_k)² + 1e-8 )^{1/2}     加权残差标准差（逐元素, d 维）
v_k   = [ μ_k ‖ σ_k ]               ∈ ℝ^{2d}      ← v2 决议：只保留这两项
δ_k   = W₂ · GELU(W₁ v_k + b₁) + b₂               写入口 bottleneck MLP: 2d → 256 → d
        初始化：W₂ ← 0.01·W₂,  b₂ ← 0
```

- 二元组 `v_k` 是对"这一段里锚点之外还残留什么信息"的有损摘要：残差往哪偏（μ）、有多分散（σ）。
- 写入口 `δ_k` 据此生成一个 d 维**修正向量**：它不是凭空造一个新 token，而是告诉锚点"你该朝哪个方向变形一点"。
- 输出层缩小 100 倍 + 偏置清零 ⇒ 训练第一步 `δ ≈ 0`，模型行为从恒等映射起步，结构上排除灾难性初始化。
- 诊断：`‖δ_k‖` 从 843 单调涨到 2098（见 §14(c) 的过拟合讨论）。

> **v2 决议（用户 2026-11-10，拍板）**：v_k 由 v1 的四元组 `[μ ‖ σ ‖ ℓ ‖ m̄] ∈ ℝ^{2d+2}` 简化为
> `[μ ‖ σ] ∈ ℝ^{2d}`。理由：① v1 固定 @58 下 `ℓ_k = ln L_k` 只取 {ln 9, ln 10} 两个近常数值，
> 写入口可当偏置吸收，删掉对 @58 性能无影响；② `m̄_k`（段内平均相似度）与 σ 信息大量重叠
> （内聚差 ⇔ 残差分散 ⇔ σ 大）。**被删通道的代价如实记录在 §15.3 注**：段长度信息从
> 显式无混淆端口退化为 μ/σ 里与内容混淆的隐式通道，多预算推理时小预算端的 regime 判别
> 变弱——这是可判据的消融项，验证指标是 n₁ 扫描曲线的平滑性而非 @58。

## 7. 第五步：门控融合 + 范数锚定 → 输出

```
g_k = tanh( γ(v_k) )                         γ 为共享小网络, 末层零初始化 (v2 决议; 见 §15.3a)
c_k = a_k + g_k · δ_k                        (use_fusion=False ⇒ g≡0，即消融对照)
c_k ← c_k · ‖a_k‖ / max(‖c_k‖, 1e-6)         范数锚定
C   = [c_0; …; c_{n₁−1}]  ∈ ℝ^{n₁×d}         按 raster 序排列 (v1: n₁=58)
```

- v1 实测中 γ 是长度为 n₁ 的**参数表**（标量，不随图像变化）；v2 把它换成由同一 v_k 驱动的
  共享网络 `gate_net`——解除唯一的预算形状硬绑定，同时让门图自适应（v1 实测门全为负、
  近乎全局常数，见 §15.1）。
- **门零初始化 ⇒ 训练起点 c_k ≡ a_k，整个压缩器是恒等映射**——不可能一开局就把 LLM 输入搞坏。
- 范数锚定使 `‖c_k‖ = ‖a_k‖` **按构造恒成立**：LLM 第一层看到的输入能量分布与真实视觉 token 完全一致，融合修正只改变方向、不改变能量。
- 诊断（关键）：`|γ|` 均值全程只有 0.0073 → 0.0113（门开得很小），但有效写入 `g_k·‖δ_k‖ ≈ 0.01 × 2098 ≈ 21`，相对锚点范数 `‖a_k‖ ≈ 49` 约 40%；同时 `cos(c_k, a_k)` 从 1.0 降到 0.89。**门虽小，方向性修正不小，而输出始终被拴在真实 token 旁边**——这就是"学习修正"而非"学习新 token"。

## 8. 输出的位置语义

C 的 58 行按 raster 顺序排列，与原 24×24 网格的行优先顺序一致。LLM 对视觉 token 的 2D 位置先验（同行/同列邻接关系）因此大致保留，无需重新设计位置编码或插值方案。

## 9. v1 历史训练目标：对冻结 LLM 的自蒸馏

> **版本边界**：本节记录已经跑完的 v1，不再作为 v2 的训练方案。用户于 2026-11-10 最新拍板：
> **v2 只保留 CE + REC 两项损失**，删除 KD、hidden 与 direction；详见 §15.3 决议 E。

教师与学生是**同一个 `f_θ`**，区别只在看到的视觉序列：

```
教师: [q ; X] → 576 行  ⟶  答案位 logits z_t,  末层 hidden h_t
学生: [q ; C] →  58 行  ⟶  答案位 logits z_s,  末层 hidden h_s
```

- 拼接方式：把 C（或 X）填进 prompt 中 `<image>` 占位符的位置，文本 token 走 LLM 词嵌入。教师与学生的问题 q、答案 y 完全相同（同 batch 同数据）。
- **压缩器的全部学习信号，都来自"怎样融合才能让 frozen LLM 的行为与内部状态不变"**——不需要任何人工标注的选择监督。

五项损失：

```
(1) L_CE  = − Σ_{t∈答案位} ln softmax(z_s)[y_t]
            学生对真实答案的交叉熵，锚住任务本身

(2) L_KD  = T² · KL( softmax(z_s/T) ‖ softmax(z_t/T) ),  T = 2
            答案位上模仿教师的答案分布（log-target KL 形式）

(3) L_hid = ‖h_s − h_t‖²_F / E[‖h_t‖²]
            答案位末层 hidden state 的相对 MSE，模仿内部表征

(4) L_dir = 1 − (1/n₁) Σ_k cos(c_k, a_k)
            方向约束：防止 c 漂离锚点流形（与 §7 的范数锚定配合）

(5) L_rec = 见 §10（decoder 重构损失）
```

总损失与系数（`train_v1.py` meta.json 同款）：

```
L = 1.0·L_CE + 1.0·L_KD + 0.05·L_hid + 0.1·L_rec + 0.01·L_dir
```

`L_KD + L_hid` 是主体：同时在答案分布与内部状态两个层面要求"压缩后等价于没压缩"。`L_dir` 很弱（0.01），只是安全带。

优化设置：AdamW，lr=2e-4，warmup 100 步后 cosine 衰减到 0.1×，β=(0.9, 0.95)，weight_decay=0.01，梯度裁剪 1.0；global batch=24（4 per rank × 6 GPU）；数据 = chartqa 28,138 + ocr_vqa 80,000 + coco 36,410 + textvqa 22,492 = **167,040 条**，固定划出 2,000 条 val 后实际训练 **165,040 条**，1 epoch（6,876 steps）。此前把 165,040 写成混合总量是算术/口径错误，本次依据运行日志更正。

## 10. 训练期专用：重构 decoder（推理时删除）

```
Q  = W_pos · PE(0…575)  ∈ ℝ^{576×128}     按 raster 位置的正弦查询
KV = W_in · C                              58 行作为 K/V
H  = Q + MHA₄(LN(Q), KV, KV)               4 头 cross-attention
H  = H + FFN(LN(H))
R  = W_out · H  ∈ ℝ^{576×d}

L_rec = MSE(R, X) / E[X²]  +  0.1 · ( 1 − (1/N) Σ_i cos(R_i, X_i) )
```

- 一个小的 cross-attention decoder：576 个位置编码查询去 58 行里"读回"全部 576 个原始嵌入。
- 第一项**尺度无关**（除以 `E[X²]`），避免因激活幅值大而主导损失；第二项保方向。
- 作用：要求 C 保留 **token 级**信息，而不是只够预测答案的那一点点。
- **推理时 decoder 直接删除，零额外开销**。
- 诊断：训练中 fused 的相对 MSE 0.807→0.704，而同锚点 base（无融合）反而 0.807→0.834 恶化——重构增益确实来自门控融合，不是在侵占任务学习。

## 11. v1 历史早停判据（训练中自动执行）

> 本节保留 v1 实际运行逻辑。v2 仅用 CE+REC 后，task_gain 与最佳 checkpoint 的 CE-only 口径按 §15.3 决议 E、§15.4 第 7 项调整，不能继续计算已经不存在的 KD。

在 step 100/200/400/600，用固定 64 条 val 样本、同锚点做 fused / base 配对比较：

```
task_gain  = (CE_base + KD_base) − (CE_fused + KD_fused)     > 0 表示任务侧变好
recon_gain = L_rec(base) − L_rec(fused)                       > 0 表示重构变好
```

（本节是 v1 历史：实际段统计为四元组 [μ ‖ σ ‖ ℓ ‖ m̄]；v2 才改为二元组 [μ ‖ σ]，门控改为 gate_net(v_k)。）

否决条件（命中任一即停）：
1. step≥200 时 task_gain 与 recon_gain 皆负；
2. 连续两次检查 task_gain < 0；
3. step≥600 时 gate≈0 且 task_gain≤0（门没打开且没收益）；
4. task 改善但 recon 反而退化；
5. task_gain 衰减到上次的一半以下。

通过条件（step≥600）：`task_gain > 0 且 recon_gain > 0` ⇒ **仅靠重构改善不算数**（防 decoder 自娱自乐）。

实际日志：step 600 判 `feasible=true`，继续训练至 ~6000 步（训练全长 1 epoch 未被截断）。

## 12. 评测协议

- 数据：MT-GQA testdev-balanced，4061 个对话 × 3 轮 = 12183 个 turn。
- 同一张图的压缩结果 C 在 3 轮对话中复用（每图只压缩一次）。
- 三模式共用：冻结 π、贪婪解码（每轮 ≤16 token）、GQA 官方 `is_correct` 口径。

random null（协议基线，逐图确定性）：

```
seed(img) = int( sha1(image_id)[:8], 16 )
idx       = sort( randperm_{seed(img)}(576) [: 58] )
Y_null    = π(X)[idx]      —— 取回后再按 raster 序重排
```

准确率与显著性：

```
acc = (1 / 3|D|) Σ_d Σ_{t=1}^{3} 1[ correct(pred_{d,t}, ref_{d,t}) ]

McNemar（turn 级配对, Yates 校正）:
  b = #{turns: v1 对 ∧ random 错}     c = #{turns: v1 错 ∧ random 对}
  χ² = (|b−c| − 1)² / (b+c)           p = P(χ²₁ ≥ χ²)
  χ² > 3.84  ⇔  p < 0.05（显著）
```

**训练末段终点（step 6840/6860，同一 log）**：`gate_abs 0.0154`（全程缓增）、`‖δ‖ 4775→5250`（写入口持续放大）、`cos(c,a) 0.694`（跌破 0.75 方向约束警戒线——但可行性否决条件是 cos<0.75 **且** gate>0.5，门小故未触发）、`H(w) 1.14 nats`。即 600 步之后的 6000 步里，修正量一直在加码、锚点方向持续偏离，而全量精度反降 0.755pp——与 §14(c) 的过拟合判断一致。

## 14. 三个公式化结论

**(a) 增益来源**：`acc(anchor-only)=50.60 < acc(random)=51.35 < acc(fused)=54.50`
⇒ medoid 锚点选择本身甚至略输随机（medoid 偏爱"平均/平滑"token，丢失独特高信息 token）；**几乎全部增益来自学习的融合 `(δ_k, g_k)`**。这也提示方法上限受锚点质量约束——换更强的锚点（每区 top-2、或可学习锚点）是自然的 v2 杠杆。

**(b) 流形安全性（结构性保证）**：`‖c_k‖ ≡ ‖a_k‖`（按构造恒等）且实测 `cos(c_k, a_k) ≥ 0.89`
⇒ LLM 输入分布漂移有界。对照旧 top-k 路线：选中的 Query 组合常落在 ViT/LLM 视觉 token 流形之外，是 LLM 输出退化的直接原因；本路线从构造上排除了该故障模式。

**(c) 过拟合 / 训练过度**：`step 2000→6000: acc ↓ 0.755`，同时 `‖δ‖: 843→2098`（step-6000）、`4775→5250`（训练末段 6860）、`cos(c,a): 1.0→0.89→0.694`、`H(w): 1.82→1.02 nats`、`gate_abs: 0.0073→0.0154`
⇒ 写入口越开越大、权重越收越窄，而 val 上的 task_gain 在 600 步后已趋平（3.126→3.203）。典型过拟合 ⇒ **推荐 checkpoint 是 val 上 (fused_ce+fused_kd) 最低的 step-2000，而非训练终点 step-6000**。控制手段（v2 候选）：更强的写入正则、更早停止、更多数据 epoch 配合 dropout。

### 15.1 门控 γ 的实测诊断（读自 `ckpt/v1_good_step2000.pt`）

```
γ_k ∈ ℝ^{58} (参数表, 不随图像变化)
tanh(γ):   全部 ∈ [−0.0181, −0.0107]
           均值 −0.0138,  标准差 0.0016
           p5 −0.0167,  中位数 −0.0137,  p95 −0.0115
段间差异 ≈ 0.007 (绝对尺度极小)
```

三条结论：

1. **门没有学会分化**：整图 p5–p95 只差 0.005，"逐段门控"名不副实，实际退化为一个全图统一的小系数 ≈ −0.014（负号源于 (δ, γ) 的符号简并，等价实现）。
2. **真正在干活的是 δ_k**：有效写入 `|g|·‖δ‖ ≈ 0.014×2098 ≈ 29 ≈ ‖a_k‖(49) 的 60%`，图自适应/段自适应能力全部来自共享 MLP 的写入口，门只提供"保守的小比例"。
3. 按原设计意图（零初始化保险、训练不崩）它**没有失职**；但"每图每段自主决定融合强度"的门控语义未实现，是 v2 最值得修的底座组件。

### 15.2 预算适应性审计（n₁ 可变性逐组件核查）

| 组件 | n₁ 可变？ | 依据 |
|---|---|---|
| 分段 `e_k = linspace(0,N,n₁+1)` | ✅ | n₁ 只是分割数，L_k 自动 ≈ N/n₁ |
| medoid 锚点 | ✅ | 逐段函数，与段数无关 |
| 残差加权 softmax | ✅ | 在 L_k 维逐段发生 |
| 段统计 v_k | ✅ | 逐段函数；**v2 决议后 v_k=[μ‖σ] 已不含 log L_k**，长度信息退为隐式通道（见 §15.3 决议 A 的代价记录） |
| 写入口 MLP δ = f(v_k) | ✅ | 逐段共享权重函数 |
| 范数锚定 / raster 序输出 | ✅ | 逐行操作 |
| prompt 拼接（`<image>` 扩展 n₁ 个） | ✅ | train/eval splice 按 `c.shape[1]` 动态 |
| 重构 decoder（576 查询） | ✅ | 576 是**输入**网格尺寸，非预算 |
| **门控 `γ ∈ ℝ^{n₁×1}`** | ❌ **形状硬绑定** | 参数表长度随 n₁ 变；换预算 `load_state_dict` 直接报错 |
| `train_v1.py` | ❌ | 无 `--n1` 参数，固定 58，无预算课程 |
| `eval_v1.py` | ❌ | `n1` 从 ckpt cfg 读（`cfg.get("n1",58)`），运行时 `--n1` 被 ckpt 覆盖 |
| decoder 的 576 维正弦 PE | ◐ 次要 | 576 属输入网格属性，换输入分辨率才需动态化 |

**结构性事实**：除 γ 外所有逐段组件都是共享权重的逐段函数 `ℝ^{L_k×d} → ℝ^d`——同一套权重在 n₁=29（L≈20）与 n₁=115（L≈5）下都能前向。γ 是**唯一把压缩率烧进参数形状**的组件；按决议 B/D 改为共享 gate_net、运行时 n₁ 与动态 prompt 后，checkpoint 才获得完整的预算无关性：

```
n₁ = N = 576 (L_k=1):  r_i≡0 → μ=σ=0；各共享网络仍可前向。
                       但训练后的 write/gate_net 偏置可以非零，不能宣称严格 C≡X。
n₁ = 1:                全图 medoid 一行                            (极限压缩)
中间任意整数 n₁:        同一权重直接前向，输出 n₁ 行               ← 框架目标
```

“任意预算”只指上述有效整数范围内的可运行性；各预算精度必须实测。

**注意**：v1 的旧 `train.py` 本来就是这个模式（`BUDGETS=[32,64,128,300]`，每步全局采样 n₁，prompt 动态拼接）；v1 化简时丢掉了该能力。

### 15.3 v2 已决议改动（2026-11-10 用户拍板；代码未动）

**决议 A（统计量简化）**：`v_k = [μ_k ‖ σ_k] ∈ ℝ^{2d}`，删除 `ℓ_k = log L_k` 与 `m̄_k`。

- 依据（用户）：固定预算训练下 ℓ 近常数、可被当偏置吸收；m̄ 与 σ 信息大量重叠。
- 代价（如实记录）：长度信息从**显式无混淆端口**退化为 μ/σ 中与内容混淆的隐式通道；
  多预算推理时小预算端（n₁≤30, L≥19）的 regime 判别变弱；原 (b) 的 L-jitter 方案随 ℓ 的
  删除一并作废。残余风险**可判据**：以 n₁ 扫描曲线（尤其 n₁=29/16 端）的平滑性为验证指标，
  不以 @58 为指标（@58 对该决议钝感）。若曲线在小预算端断崖，回退选项是只把 ℓ 加回
  （2d→2d+1，成本一个标量）或拆分输入（write 吃 [μ‖σ‖ℓ]，gate 吃 [μ‖σ‖m̄]）。

**决议 B（门控重构）**：γ 参数表 → `gate_net`（唯一形状硬绑定的解除）

```
v_k = [μ_k ‖ σ_k]                            与 δ 同一摘要（2d 端口）
g_k = tanh( gate_net(v_k) )                   gate_net: ℝ^{2d} → 64 → 1
        (Linear→GELU→Linear, 末层零初始化)
c_k = a_k + g_k · δ_k
```

为固定参数核算口径，gate_net 隐层明确为 **64**（与原估计“约增加 0.5M 参数”一致）。一处改动同时解决三个问题：① 参数表不再含 n₁，checkpoint 预算无关；② 门终于图自适应（γ 全负常数的问题消失）；③ 与 δ 共享同一 v_k 端口，无新特征工程。同时 v_k 从单消费者（write）变双消费者（write + gate_net）。

**决议 C（训练协议）**：固定 @58 训练不变，**不做**预算课程（用户明确：训练固定压缩率，只保证推理换预算）。

**决议 D（checkpoint / 任意有效预算推理）**

`train_v2.py` 的 `compressor_config` 不再写 `n1`；`eval_v2.py` 构造时忽略 ckpt cfg 里的 n1（v1 此处有坑：`--n1` 传了也被 ckpt 覆盖），前向传运行时 `--n1`。分段、medoid、残差聚合、write、gate_net、范数锚定均为逐段共享操作，模型 `state_dict` 中不得存在任何形状依赖 n₁ 的参数。

**支持范围的准确含义**：对当前固定输入网格 N=576，同一 checkpoint 在**任意整数 n₁∈[1,576]** 上都可直接前向，输出 n₁ 行，无需重训或改变参数形状；n₁ 同时控制压缩器和 prompt 中的图像占位符数量。推理必须 `need_recon=False`，重构 decoder 不参与推理。n₁>576 会产生空段，不属于有效压缩预算；更换输入分辨率/输入 token 数 N 也不在本决议的保证范围内。

这保证的是**结构与接口的预算无关性**，不是任意预算下精度不退化。固定 @58 训练后的多预算泛化必须由 §15.5 的扫描实测，尤其不能预先承诺 n₁=1、16、29 等极低预算的精度。

**决议 E（训练损失精简；用户最新拍板）**：v2 **只使用答案 CE 与视觉重构 REC 两项损失**：

```
L_v2 = 1.0 · L_CE + 0.1 · L_rec
L_rec = 归一化重构 MSE + 0.1 · 重构余弦方向损失     （沿用 v1，未调参）
```

- 删除答案 KD、末层 hidden-state 距离、锚点 direction 损失；不再执行教师前向，学生也无需返回 hidden states。
- CE 直接监督真实答案；REC 保留全图 576-token 的稠密视觉监督。两项职责不重叠。
- **范数锚定是模型结构，不随 direction 损失删除**。anchor_cos 继续作为诊断量记录，但不再反向传播为损失。
- REC 外层权重 0.1、内部余弦权重 0.1 都只是 v1 沿用值，**没有系统调参记录，不视为最优值**；首轮先固定，避免与损失删减同时引入额外变量。
- 早停与选模同步改为只看 CE + REC：`task_gain = CE_base − CE_fused`，最佳 checkpoint 按验证集 `fused_ce` 最低选择，不再使用 `fused_ce + fused_kd`。
- v1 的 54.9618 来自五项损失，不能作为 CE+REC 已经取得的结果；v2 必须从头重训，不能直接加载 v1 权重宣称等价。

### 15.5 v2 验证协议（按最新两损失与预算决议执行）

1. **两损失基线**：仅用 CE+REC 从随机初始化重训，固定 @58；先按验证集 CE 选 checkpoint，再做 MT-GQA 全量评测。v1 的 54.9618 与同协议 random 52.5404 只作历史参照，不能预设两损失一定不退化。
2. **任意预算结构测试**：同一个 checkpoint 不改权重，在 n₁=1 与 n₁=576 边界及若干中间值检查前向、输出行数、prompt 拼接和生成；压缩器侧可遍历全部 1…576 个整数预算做 shape/有限值测试。该测试验证“任何有效压缩率都能运行”，不替代精度评测。
3. **money experiment**：单一 ckpt 只改 `--n1`，`n₁ ∈ {288,144,115,86,58,38,29,16}` 全量评测，形成精度–压缩率曲线，无需逐点重训。此曲线同时检验决议 A 的长度信息风险与固定 @58 训练的预算泛化。
4. 每点配 v2 协议 random null（逐图 sha1 seed，n₁ 同步），做每预算点独立 McNemar 显著性检验。
5. 若小预算端断崖，先区分“统计量缺长度信息”与“单 medoid 代表性不足”：前者回退见决议 A，后者再考虑每段双锚点/分层合并；不得用结构可前向替代精度结论。
6. **损失消融边界**：v2 本身就是相对 v1 的 CE+REC 精简实验；若要证明 REC 权重或 CE/REC 各自必要性，需另做同数据、同步数对照，不能从 v1 日志补推。
7. 仍待补齐：同协议 strat_random 强基线、锚点质量消融、过拟合控制、ChartQA/TextVQA 域外泛化，以及训练混合与 GQA 关系的声明。
